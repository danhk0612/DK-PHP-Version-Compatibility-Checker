# T18 — 카탈로그 v2 엔진 갱신·복원

T16 계약에 따른 Windows x64 검증 대상으로, 현재 T17의 검증 팩을 기반으로 준비합니다.

## 포함 범위

- 카탈로그 `schemaVersion=2`의 양의 정수 `releaseSequence`·중복 배포 순서·중복 팩 SHA 거부.
- 엔진 팩의 manifest는 `schemaVersion=1`, JSON 결과 형식은 `phpcs4-json-v1` 유지.
- 기존 팩 목표 목록을 보존하면서 더 높은 배포 순서의 팩만 업데이트로 제공. 목표가 늘지 않아도 새 팩 식별자/해시이면 업데이트로 처리.
- 새 관리형 설치 활성화 포인터에 배포 순서를 보존. 구형 포인터에 순서가 없으면 카탈로그의 ID·ZIP/manifest 해시로 확인하며 확인 불가 시 업데이트 중단.
- 사용자 요청 시에만 조회/설치. 패키징·검사 실행 중 자동 통신·핫스왑 없음.
- 이전 검증 팩/기본 동봉 팩 복원. 복원은 다음 프로그램 실행에서 적용.

## 통합 검증

`tests/t10/prepare_packs.py`에서 기존 `reduced`/`full` 시험 팩 외에 **같은 목표를 갖고 packId·검증 증거가 다른** `full-updated` 파생 검증 팩을 만듭니다. 엔진 라이브러리 버전은 일부러 바꾸지 않아 임의 가짜 새 엔진 버전을 만들지 않습니다. 여기서는 **업데이트 선택·활성화 로직이 목표 개수 차이에 의존하지 않는지**를 증명합니다.

`tests/t14/T14.Verification.csproj`의 Windows 실제 installer/GUI 시험을 재사용합니다. 배포 순서 1→2→3 중 2→3은 목표 목록 동일이며, 기존 기능의 다운로드 중단·해시 오류·원본 불변·재시작을 회귀 검증합니다. 3→2 일반 업데이트 거부, 3→2 이전 팩 복원, 내장 팩 복원도 실측합니다.

**제한:** 새 실제 PHPCS/PC 패키지 버전은 이 시험에서 받거나 검증하지 않습니다. 미래 PHP 신규 규칙과 배포 채널·라이선스 고지는 별도 관문입니다. Windows CI를 통과하기 전에는 이 설계/코드를 완료 처리하지 않습니다.
