# 검증된 엔진 팩 다운로드 계약

T14는 사용자가 GUI에서 엔진 팩 확인을 선택할 때 목록을 읽습니다. 현재 목표를 모두 유지하면서 새 목표를 추가하는 첫 팩을 표시하고, 사용자가 확인하면 다운로드합니다. 목록 순서는 발행자가 정합니다. 설치가 성공하면 현재 창은 기존 팩을 계속 사용합니다. 새 실행에서 설치된 팩을 읽고, 유효하지 않으면 이전 검증 팩과 기본 내장 팩을 순서대로 확인합니다. 검사와 시작에는 목록 서버 접속이 필요하지 않습니다. 설치 후 다음 실행까지 같은 창에서는 추가 다운로드를 잠급니다.

## 목록과 ZIP

제품에는 승인된 단일 카탈로그 HTTPS 주소를 지정합니다. 현재 주소는 미설정입니다. 제품용 주소는 이 저장소의 GitHub raw main 경로를 사용하며, 팩 ZIP과 대응 소스 ZIP은 같은 저장소의 태그별 GitHub Release 자산으로 제공하는 계약입니다. 실제 자산과 목록을 준비할 때 T08/T09 배포 조건 및 게시 승인을 적용합니다.

목록은 UTF-8 JSON 객체입니다. 최상위 `schemaVersion`은 1이며 `packs`는 배열입니다. 각 행에 다음 값이 필요합니다.

| 필드 | 값 |
| --- | --- |
| `packId` | 검증 팩 manifest의 `packId` |
| `packSchemaVersion`, `reportProfile` | 현재 팩은 1과 `phpcs4-json-v1` |
| `assetUrl`, `sourceUrl` | 정확한 태그별 팩 ZIP 및 대응 소스·고지 ZIP URL |
| `archiveBytes`, `archiveSha256` | 완성된 팩 ZIP의 바이트 수와 소문자 SHA-256 |
| `manifestSha256` | ZIP의 `runtime/manifest.json` 원본 바이트에 대한 소문자 SHA-256 |
| `phpRuntimeVersion` | manifest의 `runtime.version` |
| `engineVersions` | manifest의 `engine.versions` 객체 전체 |
| `targets` | manifest 순서대로 각 `version`과 `limitations` |

검증 팩의 manifest와 php·engine·verification을 ZIP의 `runtime/`에 그대로 넣습니다. 별도 고지가 필요하면 `notices/`에 둘 수 있습니다. ZIP 경로 구분자는 `/`입니다. 목록 256 KiB, ZIP 128 MiB, 풀린 데이터 256 MiB, ZIP 항목 4,096개를 상한으로 둡니다. 설치기는 경로 탈출, 링크, 중복·대소문자 충돌, Windows 예약 이름을 거부합니다.

새 PHP 목표가 생기면 먼저 [팩 준비 절차](README.md)의 양성·음성 대조 및 기존 회귀를 실행합니다. 생성된 manifest와 ZIP에 맞춰 카탈로그 행을 작성합니다. 같은 팩 스키마와 보고서 형식을 사용하는 새 목표는 C#이나 XAML에서 버전 번호를 바꿀 필요가 없습니다.

## 설치와 실패 처리

다운로드와 설치는 검사 대상과 분리한 `%LOCALAPPDATA%/DK-PHP-Version-Compatibility-Checker/engines`에서 실행합니다. 검사 대상 경로를 서버로 보내지 않습니다. 팩을 실행하기 전에 ZIP과 manifest 해시, 엔진 구성·목표·검증 결과를 대조합니다. 같은 사용자 계정의 프로그램 관리 영역을 신뢰 경계로 삼습니다. 카탈로그 권한은 앱에 지정한 저장소·경로와 HTTPS 연결에 의존합니다.

다운로드 실패나 취소는 기존 팩과 선택 정보를 보존합니다. 설치가 끝난 팩은 ZIP 해시별 폴더에 둡니다. 손상된 설치 폴더는 자동으로 삭제하지 않으므로 같은 ZIP으로 복구하려면 앱을 닫은 뒤 해당 손상 폴더를 따로 옮겨야 합니다. 다른 검증 팩이나 내장 팩은 사용할 수 있습니다.


## T16 — 엔진 갱신 카탈로그 v2 계약 (설계 확정, 구현은 T18)

위 내용은 **현재 제품의 v1 구현 계약**입니다. v0.1.0은 승인 카탈로그 URL이 `null`이고 온라인 메뉴가 숨겨져 있습니다. 아래 v2는 T18에서 구현할 다음 계약이며, T16 문서 작업만으로 동작하지 않습니다.

- 활성 엔진은 하나이며 설치/업데이트/복원 후 **다음 실행**부터 변경합니다. 기본 내장 팩을 항상 보존합니다.
- 카탈로그 최상위 `schemaVersion=2`를 사용합니다. 기존 팩 ZIP의 `runtime/manifest.json`은 `schemaVersion=1`, `reportProfile=phpcs4-json-v1`을 유지합니다. 서로 다른 두 버전 번호를 혼용하지 않습니다.
- 기존 `packs[]`의 필수 항목과 URL 출처·크기·해시·경로·목표/근거 검증을 전부 유지합니다. v2 각 행에 양의 정수 `releaseSequence`를 추가합니다. 이는 프로젝트가 발행한 **엔진 팩 배포 순서**이며 PHP/PHPCS 버전이나 날짜가 아닙니다.
- `releaseSequence`는 게시 후 변경하거나 재사용하지 않습니다. 서로 다른 팩은 서로 다른 순서를 갖고, 같은 순서로 서로 다른 해시/ID를 게시할 수 없습니다. 각 팩의 `packId`와 ZIP/manifest 해시는 불변입니다. 과거 카탈로그 항목도 보존해 이미 설치된 팩의 순서를 확인할 수 있게 합니다.
- 후보는 현재 활성 팩과 **다른 검증 팩**이며 활성 팩의 목표를 모두 포함해야 합니다. 후보의 `releaseSequence`가 활성 팩보다 큰 경우만 일반 업데이트 후보로 삼습니다. 목표 개수 증가를 필수 조건으로 삼지 않습니다. 조건을 충족하는 팩이 여럿이면 `releaseSequence`가 가장 큰 팩 하나를 제시합니다.
- **내장 기본 팩은 배포 순서 0**으로 취급합니다. 관리형 설치에서는 선택된 후보의 `releaseSequence`를 활성화 메타데이터에 함께 보존합니다. 이전 v1 관리형 팩은 카탈로그에서 `packId`와 실제 manifest/ZIP 해시를 대조해 순서를 확인하며, 순서를 확정할 수 없으면 자동 업데이트 판단을 하지 않고 기존 팩을 유지합니다. 알 수 없는 팩을 임의로 구버전(0)으로 간주하지 않습니다.
- 최신 팩이 현재 팩과 동일한 목표 목록을 가지더라도, 엔진 또는 PHP CLI 등이 변경된 별도 검증 팩이면 업데이트 후보가 될 수 있습니다. 반대로 목표 개수가 늘었더라도 순서가 낮거나 검증 근거가 없으면 업데이트로 제공하지 않습니다.
- 후보의 `packSchemaVersion=1`, `reportProfile=phpcs4-json-v1`, 필수 엔진 파일 경로·잠금 파일·Windows 실행 조건을 현재 앱이 이해하지 못하면 **설치를 거부**합니다. 단순히 엔진 패키지 버전 문자열이 새롭다는 이유로 호환된다고 판단하지 않습니다.
- 새 팩은 다운로드 → 크기/해시 확인 → ZIP 경로/manifest·lock/검증 자료 확인 → 설치 → 활성화 지표 교체 순으로 처리합니다. 변경 실패 시 현재 활성 팩은 유지합니다. 이전 검증 팩·내장 팩 복원 경로를 제공합니다. 실행 중인 검사 프로세스의 팩을 변경하지 않습니다.
- 업데이트 확인은 **사용자 요청 시에만** 카탈로그를 가져오고, 설치는 비교 내용을 보여준 뒤 **사용자 확인 후에만** 진행합니다. 시작·검사·오프라인 환경에서는 네트워크가 필요하지 않습니다.
- 검증 팩에 과거 목표 `7.4`, `8.0`, `8.1`을 추가하려면 신규 목표별 양성/음성, 기존 `8.2`~`8.5` 회귀, Windows x64 실행, JSON/종료/원본 불변·오프라인 시험 및 알려진 한계 기록을 먼저 완료해야 합니다. T17 이전에는 지원으로 표시하지 않습니다.
- 카탈로그는 기존대로 이 저장소의 승인된 HTTPS raw 경로, 팩/대응 소스는 같은 저장소의 태그 고정 Release 자산을 사용합니다. 새 엔진 구성의 재배포 고지·대응 소스·라이선스 검증은 T08/T09 배포 관문을 다시 통과해야 합니다.
- 초기 제품에 카탈로그 주소가 없어 **최초 한 번은 앱 릴리스 업데이트가 필요**합니다. 그 뒤에는 위 실행/보고 계약에 호환되는 팩만으로 목표 버전 또는 엔진을 갱신할 수 있습니다. 모든 미래 엔진과 PHP 버전의 무조건 호환을 약속하지 않습니다.

T18 검증 기준: 같은 목표의 새 엔진 팩/새 목표 포함 팩 허용, 동일 팩/오래된 팩/목표 누락/비호환/서명되지 않은 임의 URL 거부, 순서 불명 v1 팩 유지, 정상/중단/오류/오프라인 및 이전 팩 복원. T19의 GUI는 이 결과를 조회해 표시하며 카탈로그 선택 규칙을 중복 구현하지 않습니다.
